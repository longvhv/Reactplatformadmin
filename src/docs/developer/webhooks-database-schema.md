## Overview

The `webhooks` table stores all webhook subscriptions in the system. It implements a complete webhook management solution with:

- ✅ **Event subscriptions** using PostgreSQL ARRAY type
- ✅ **HMAC signature** support with secret_key
- ✅ **Failure tracking** with auto-disable threshold
- ✅ **Optimistic locking** (version field)
- ✅ **Tenant isolation** via tenant_id
- ✅ **GIN indexes** for efficient array queries
- ✅ **Full audit trail** (created_at, updated_at)

### Key Statistics

- **Total Fields:** 9
- **Indexes:** 2 (including 1 GIN index)
- **Foreign Keys:** 1
- **Check Constraints:** 3
- **Array Fields:** 1 (subscribed_events)
- **Special Types:** TEXT[] for events

## Table Structure

### Complete Table Definition

```sql
CREATE TABLE webhooks (
    -- ═══════════════════════════════════════════════════════════════
    -- I. ĐỊNH DANH & TENANCY
    -- ═══════════════════════════════════════════════════════════════
    _id UUID PRIMARY KEY,                    -- UUID v7 sinh từ ứng dụng
    tenant_id UUID NOT NULL,                 -- FK to tenants._id
    
    -- ═══════════════════════════════════════════════════════════════
    -- II. CẤU HÌNH KỸ THUẬT
    -- ═══════════════════════════════════════════════════════════════
    target_url TEXT NOT NULL,                -- Webhook endpoint URL
    secret_key TEXT NOT NULL,                -- Secret for HMAC-SHA256 signing
    subscribed_events TEXT[] NOT NULL,       -- Array of event names
    
    -- ═══════════════════════════════════════════════════════════════
    -- III. TRẠNG THÁI VẬN HÀNH
    -- ═══════════════════════════════════════════════════════════════
    is_active BOOLEAN NOT NULL DEFAULT TRUE, -- Active status
    failure_count INT NOT NULL DEFAULT 0,    -- Consecutive failures
    
    -- ═══════════════════════════════════════════════════════════════
    -- IV. AUDIT & VERSIONING
    -- ═══════════════════════════════════════════════════════════════
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    version BIGINT NOT NULL DEFAULT 1,       -- Optimistic locking

    -- ═══════════════════════════════════════════════════════════════
    -- V. CÁC RÀNG BUỘC (CONSTRAINTS)
    -- ═══════════════════════════════════════════════════════════════
    CONSTRAINT fk_webhook_tenant 
        FOREIGN KEY (tenant_id) 
        REFERENCES tenants(_id)
        ON DELETE CASCADE
        ON UPDATE CASCADE,
        
    CONSTRAINT chk_webhook_url_fmt 
        CHECK (target_url ~* '^https?://'),
        
    CONSTRAINT chk_webhook_fail_count 
        CHECK (failure_count >= 0),
        
    CONSTRAINT chk_webhook_version 
        CHECK (version >= 1)
);
```

## Field Definitions

### Section I: ĐỊNH DANH & TENANCY

#### `_id` UUID PRIMARY KEY

**Type:** UUID  
**Constraints:** PRIMARY KEY, NOT NULL  
**Description:** Unique identifier for the webhook

**Best Practice:**
- Use UUID v7 for time-ordered IDs
- Generated by application layer
- Never reuse deleted webhook IDs

**Example:**
```sql
_id = '01934c8f-1a2b-7c3d-8e4f-5a6b7c8d9e0f' -- UUID v7
```

---

#### `tenant_id` UUID NOT NULL

**Type:** UUID  
**Constraints:** FOREIGN KEY to tenants(_id), NOT NULL  
**Description:** ID of the tenant that owns this webhook

**Business Rules:**
- Each webhook belongs to exactly one tenant
- Cannot be NULL
- Must reference existing tenant
- Cascade delete when tenant is deleted

**Index:** Covered by `idx_webhooks_tenant_list`

**Example:**
```sql
tenant_id = '01934c8f-0000-7c3d-8e4f-000000000001'
```

---

### Section II: CẤU HÌNH KỸ THUẬT

#### `target_url` TEXT NOT NULL

**Type:** TEXT  
**Constraints:** NOT NULL, CHECK (URL format)  
**Description:** The webhook endpoint URL

**Validation:**
- Must be a valid HTTP or HTTPS URL
- Regex: `^https?://`
- Recommended: HTTPS only in production
- Max length: Unlimited (TEXT type)

**Example:**
```sql
target_url = 'https://api.example.com/webhooks'
```

**Security Note:**
- Always use HTTPS in production
- Validate URL format before saving
- Consider IP whitelisting

---

#### `secret_key` TEXT NOT NULL

**Type:** TEXT  
**Constraints:** NOT NULL  
**Description:** Secret key for HMAC-SHA256 signature verification

**Format:** `whsec_{uuid}`

**Generation:**
```typescript
function generateSecretKey(): string {
  return `whsec_${uuidv4()}`;
}
```

**Example:**
```sql
secret_key = 'whsec_a1b2c3d4-e5f6-7890-abcd-ef1234567890'
```

**Security:**
- ✅ Auto-generated if not provided
- ✅ Never log or display in plain text
- ✅ Rotate periodically (every 90 days)
- ✅ Use for HMAC-SHA256 signing

**Usage:**
```typescript
import crypto from 'crypto';

function signPayload(payload: string, secret: string): string {
  return crypto
    .createHmac('sha256', secret)
    .update(payload)
    .digest('hex');
}
```

---

#### `subscribed_events` TEXT[] NOT NULL

**Type:** TEXT[]  (PostgreSQL ARRAY)  
**Constraints:** NOT NULL  
**Description:** Array of event names the webhook is subscribed to

**Index:** GIN index for efficient array operations

**Example:**
```sql
subscribed_events = ARRAY[
  'user.created',
  'user.updated',
  'order.paid',
  'subscription.renewed'
]
```

**Query Operations:**
```sql
-- Check if event is subscribed
WHERE 'user.created' = ANY(subscribed_events)

-- Check if contains multiple events
WHERE subscribed_events @> ARRAY['user.created', 'order.paid']

-- Find all unique events
SELECT DISTINCT UNNEST(subscribed_events) FROM webhooks;
```

**Business Rules:**
- Cannot be empty array
- Event names should follow pattern: `{category}.{action}`
- Case-sensitive matching
- No duplicates in array

### Section III: TRẠNG THÁI VẬN HÀNH

#### `is_active` BOOLEAN NOT NULL DEFAULT TRUE

**Type:** BOOLEAN  
**Constraints:** NOT NULL, DEFAULT TRUE  
**Description:** Whether the webhook is active and receiving events

**Values:**
- `TRUE` - Webhook is active, events will be delivered
- `FALSE` - Webhook is disabled, events are skipped

**Auto-disable Logic:**
```sql
-- Automatically disabled when failure_count >= 5
UPDATE webhooks
SET is_active = FALSE
WHERE failure_count >= 5;
```

**Manual Reset:**
```sql
-- Admin can manually reactivate
UPDATE webhooks
SET 
  is_active = TRUE,
  failure_count = 0,
  version = version + 1
WHERE _id = $1;
```

---

#### `failure_count` INT NOT NULL DEFAULT 0

**Type:** INTEGER  
**Constraints:** NOT NULL, DEFAULT 0, CHECK >= 0  
**Description:** Number of consecutive delivery failures

**Behavior:**
- Incremented on each failed delivery
- Reset to 0 on successful delivery
- Triggers auto-disable at threshold (5)

**Threshold Logic:**
```sql
-- Check if should disable
IF failure_count >= 5 THEN
  UPDATE SET is_active = FALSE
END IF
```

**Reset:**
```sql
-- After successful delivery
UPDATE webhooks
SET failure_count = 0
WHERE _id = $1;
```

**Monitoring:**
```sql
-- Find webhooks with high failure count
SELECT _id, target_url, failure_count
FROM webhooks
WHERE failure_count > 0
ORDER BY failure_count DESC;
```

#### `version` BIGINT NOT NULL DEFAULT 1

**Type:** BIGINT  
**Constraints:** NOT NULL, DEFAULT 1, CHECK >= 1  
**Description:** Version number for optimistic locking

**Purpose:** Prevent concurrent update conflicts

**Usage:**
```sql
-- Update with version check
UPDATE webhooks
SET 
  target_url = $1,
  version = version + 1,
  updated_at = NOW()
WHERE _id = $2
AND version = $3  -- Optimistic lock check
RETURNING version;

-- If 0 rows affected → version conflict
```

**Conflict Handling:**
```typescript

    throw new Error('Version conflict - webhook was updated by another process');

  // Reload webhook and retry
```

## Indexes

### 1. Primary Key Index (Automatic)

```sql
-- Automatically created with PRIMARY KEY
CREATE UNIQUE INDEX webhooks_pkey ON webhooks (_id);
```

**Purpose:** Unique constraint and fast lookup by ID

**Performance:** O(log n) - ~3ms for 1M rows

---

### 2. GIN Index for Active Events

```sql
CREATE INDEX idx_webhooks_active_events 
ON webhooks USING GIN (subscribed_events) 
WHERE is_active = TRUE;
```

**Purpose:** 
- Fast event-based filtering
- Efficient array contains operations
- Only indexes active webhooks

**Queries Optimized:**
```sql
-- Find webhooks for event (uses GIN index)
SELECT target_url, secret_key
FROM webhooks
WHERE is_active = TRUE
AND 'user.created' = ANY(subscribed_events);
```

**Performance:** O(log n) - ~5-10ms for 10K rows

**Size:** ~30% smaller than full table index (partial index)

---

### 3. Tenant List Index

```sql
CREATE INDEX idx_webhooks_tenant_list 
ON webhooks (tenant_id, created_at DESC);
```

**Purpose:**
- Fast tenant webhook listing
- Supports sorting by date
- Efficient pagination

**Queries Optimized:**
```sql
-- List tenant webhooks (uses this index)
SELECT *
FROM webhooks
WHERE tenant_id = $1
ORDER BY created_at DESC
LIMIT 20;
```

**Performance:** ~10-15ms for tenant with 100 webhooks

## Constraints

### 1. Foreign Key Constraint

```sql
CONSTRAINT fk_webhook_tenant 
    FOREIGN KEY (tenant_id) 
    REFERENCES tenants(_id)
    ON DELETE CASCADE
    ON UPDATE CASCADE
```

**Behavior:**
- ✅ Cannot create webhook for non-existent tenant
- ✅ Deleting tenant deletes all its webhooks
- ✅ Updating tenant ID cascades to webhooks

---

### 2. URL Format Constraint

```sql
CONSTRAINT chk_webhook_url_fmt 
    CHECK (target_url ~* '^https?://')
```

**Purpose:** Ensure URL is valid HTTP/HTTPS format

**Validation:**
- Must start with `http://` or `https://`
- Case-insensitive check (`~*`)

**Example:**
```sql
-- ✅ Valid
target_url = 'https://example.com/webhooks'
target_url = 'http://localhost:3000/webhooks'

-- ❌ Invalid
target_url = 'ftp://example.com'
target_url = 'example.com/webhooks'
```

---

### 3. Failure Count Constraint

```sql
CONSTRAINT chk_webhook_fail_count 
    CHECK (failure_count >= 0)
```

**Purpose:** Ensure failure_count is never negative

---

### 4. Version Constraint

```sql
CONSTRAINT chk_webhook_version 
    CHECK (version >= 1)
```

**Purpose:** Ensure version starts at 1 and never goes below

## Migration Scripts

### Initial Table Creation

```sql
-- 1. Create table
CREATE TABLE webhooks (
    _id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,
    target_url TEXT NOT NULL,
    secret_key TEXT NOT NULL,
    subscribed_events TEXT[] NOT NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    failure_count INT NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    version BIGINT NOT NULL DEFAULT 1,
    
    CONSTRAINT fk_webhook_tenant FOREIGN KEY (tenant_id) REFERENCES tenants(_id) ON DELETE CASCADE,
    CONSTRAINT chk_webhook_url_fmt CHECK (target_url ~* '^https?://'),
    CONSTRAINT chk_webhook_fail_count CHECK (failure_count >= 0),
    CONSTRAINT chk_webhook_version CHECK (version >= 1)
);

-- 2. Create indexes
CREATE INDEX idx_webhooks_active_events 
ON webhooks USING GIN (subscribed_events) 
WHERE is_active = TRUE;

CREATE INDEX idx_webhooks_tenant_list 
ON webhooks (tenant_id, created_at DESC);

-- 3. Create trigger for updated_at
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ language 'plpgsql';

CREATE TRIGGER update_webhooks_updated_at
BEFORE UPDATE ON webhooks
FOR EACH ROW
EXECUTE FUNCTION update_updated_at_column();
```

## Example Queries

### 1. Create Webhook

```sql
INSERT INTO webhooks (
  _id,
  tenant_id,
  target_url,
  secret_key,
  subscribed_events,
  is_active,
  failure_count,
  created_at,
  updated_at,
  version
) VALUES (
  gen_random_uuid(),
  '01934c8f-0000-7c3d-8e4f-000000000001',
  'https://example.com/webhooks',
  'whsec_' || gen_random_uuid()::text,
  ARRAY['user.created', 'order.paid'],
  TRUE,
  0,
  NOW(),
  NOW(),
  1
)
RETURNING *;
```

---

### 2. Find Webhooks for Event

```sql
SELECT 
  _id,
  tenant_id,
  target_url,
  secret_key,
  failure_count
FROM webhooks
WHERE is_active = TRUE
AND 'user.created' = ANY(subscribed_events)
ORDER BY created_at ASC;
```

---

### 3. List Tenant Webhooks

```sql
SELECT 
  w._id,
  w.target_url,
  w.subscribed_events,
  w.is_active,
  w.failure_count,
  w.created_at,
  t.name as tenant_name
FROM webhooks w
JOIN tenants t ON w.tenant_id = t._id
WHERE w.tenant_id = $1
ORDER BY w.created_at DESC
LIMIT 20;
```

---

### 4. Update Webhook with Version Check

```sql
UPDATE webhooks
SET 
  target_url = $1,
  subscribed_events = $2,
  version = version + 1,
  updated_at = NOW()
WHERE _id = $3
AND version = $4
RETURNING _id, version;
```

---

### 5. Increment Failure Count

```sql
UPDATE webhooks
SET 
  failure_count = failure_count + 1,
  is_active = CASE 
    WHEN failure_count + 1 >= 5 THEN FALSE 
    ELSE is_active 
  END,
  version = version + 1,
  updated_at = NOW()
WHERE _id = $1
RETURNING failure_count, is_active;
```

---

### 6. Reset Failures

```sql
UPDATE webhooks
SET 
  failure_count = 0,
  is_active = TRUE,
  version = version + 1,
  updated_at = NOW()
WHERE _id = $1
RETURNING *;
```

## Best Practices

### 1. Security

✅ **Always use HTTPS** for target_url in production  
✅ **Rotate secret_key** every 90 days  
✅ **Validate URLs** before saving  
✅ **Never log secret_key** in plain text  

### 2. Performance

✅ **Use indexes** for all queries  
✅ **Limit array size** (max 50 events per webhook)  
✅ **Archive old webhooks** (soft delete pattern)  
✅ **Monitor index usage** regularly  

### 3. Reliability

✅ **Implement retry logic** with exponential backoff  
✅ **Set failure threshold** (auto-disable at 5)  
✅ **Monitor failure_count** in dashboards  
✅ **Alert on high failure rates**  

### 4. Maintenance

✅ **Clean up inactive webhooks** periodically  
✅ **Review event subscriptions** quarterly  
✅ **Vacuum table** after bulk deletes  
✅ **Reindex** after major updates
